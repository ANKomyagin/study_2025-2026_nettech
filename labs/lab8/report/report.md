# Цель работы

Цель работы — изучение принципов маршрутизации в IPv4- и IPv6-сетях и принципов настройки сетевого оборудования. 

# Задание

Требуется задокументировать моделируемую сеть (схемы L1 и L3, таблицы адресации), настроить двойной стек IPv4/IPv6, а также настроить динамическую маршрутизацию по протоколам RIP/RIPng и OSPF (OSPFv2/OSPFv3), проверить связность, пути прохождения пакетов и проанализировать захваченный трафик.

## Динамическая маршрутизация RIP/RIPng

### RIP для IPv4

RIP — дистанционно-векторный протокол; в RIPv2 обновления передаются на multicast-адрес 224.0.0.9, а метрика определяется числом транзитных переходов. 

На всех маршрутизаторах включён RIP версии 2 и добавлены сети через перечисление интерфейсов (network ethX) согласно методике задания. 

![Конфигурация RIP (RIPv2) на msk-ankomyagin-gw-01](image/22.png){#fig:822}

![Конфигурация RIP (RIPv2) на msk-ankomyagin-gw-02](image/23.png){#fig:823}

### RIPng для IPv6

Для IPv6 используется RIPng, который отправляет обновления на multicast-адрес FF02::9, при этом маршрутизация включается на уровне интерфейса. 

На всех маршрутизаторах настроен RIPng, добавлены интерфейсы network ethX по заданию, затем выполнена проверка и тестирование путей.

## Динамическая маршрутизация OSPF (OSPFv2/OSPFv3)

### OSPFv2 для IPv4

OSPF — протокол маршрутизации по состоянию канала; в IPv4 используется OSPFv2 и multicast-адреса 224.0.0.5 и 224.0.0.6 для служебного обмена. 

На маршрутизаторах настроен OSPFv2 в area 0.0.0.0 с объявлением сетей командой network для соответствующих IPv4-подсетей. 

![Конфигурация OSPFv2 на msk-ankomyagin-gw-01 (area 0)](image/43.png){#fig:843}

![Проверка маршрутов OSPFv2 (show ip ospf route)](image/48.png){#fig:848}

![Ping/trace (IPv4) при OSPFv2 до/после отказа линка](image/49.png){#fig:849}

# Выводы

В ходе работы задокументирована топология и адресация стенда, настроен двойной стек IPv4/IPv6 и проверена базовая связность согласно заданию. 

Для IPv4 и IPv6 настроены протоколы динамической маршрутизации RIP/RIPng и OSPFv2/OSPFv3, выполнены проверки ping/trace и показана реакция сети на отказ интерфейса (перестроение маршрута). 

Анализ захваченного трафика позволил выделить служебные рассылки протоколов маршрутизации (например, RIPv2 на 224.0.0.9, RIPng на FF02::9, а также OSPF на 224.0.0.5/224.0.0.6 и FF02::5/FF02::6) и связать их с этапами сходимости маршрутов.
